# 把笔记整理成知识图谱数据

这套规则用于把 `行测知识/<科目>/<模块>/*.md` 转成 `src/data/.../*.ts`。
目标不是「一篇笔记一张图」，而是「一个专题一张大图」：通常合并 2–5 篇笔记，节点 20–40 个。

## 硬规则

1. **一个节点 = 一个可独立成题的考点**。节点标题用笔记里的原词，不自造术语。
2. 年份、人名、地名、文件、数字**只从笔记取**；笔记 `## 6 待核对` 里的内容不进图。
3. 每个节点写 `refs`，如 `P3 §2.7`，方便回查。
4. 关系只用五种：`time` 时间先后、`cause` 因果演进、`part` 隶属包含、`contrast` 易混对比、`origin` 起源。
   - 易混一律 `contrast`（红色虚线），边上写清「区别是什么」，不要只写「易混」。
5. 口诀只保留笔记 `## 5 记忆口诀` 已有的，不新编。
6. 图内不放长段落：`summary` ≤ 24 字，边 `label` ≤ 10 字。展开内容留给后续的详情弹层。
7. 时间轴上的 `year` 只用于排序与定位；展示用 `sub`。没有明确日期的，`sub` 写「19 世纪中叶」这类区间，不要编具体日子。

## 一张新图怎么做

1. 选定专题（如「土地革命」「中共会议链」），确定覆盖哪几篇笔记的哪些章节。
2. 先列「讲什么」：
   - 主线是什么（时间？会议？概念树？）；
   - 有哪几条支线；
   - 哪几组是考试最容易挖坑的易混。
3. 选布局：
   - `timeline`：一条时间主线 + 阶段色带（总览、文学史、古代史）；
   - `columns`：一个阶段几条并行线（建军 / 根据地 / 长征）；
   - `chain`：一串有先后因果的节点（会议链、战役链、理论演进）。
4. 写数据文件 `src/data/<模块>/<科目>/<图 id>.ts`，导出 `satisfies KnowledgeMap`。
5. 在 `src/data/registry.ts` 的对应科目 `maps` 数组里加一行。
6. 运行 `npm run dev`，对照下面清单自检。

## 自检清单

- [ ] 笔记 `## 0 考点速览` 的每一条，都能在图中找到节点或说明；
- [ ] `## 3 时间线 / 对比表` 的每一行，都有节点或边；
- [ ] `## 4 易混辨析` 的每一行，都有 `contrast` 边或图注；
- [ ] 随便抽 10 个年份 / 人名 / 文件名，与原文一致；
- [ ] 没有把 ASR 同音字写成正确名词；
- [ ] 每个节点都有 `refs`；
- [ ] 在 1440×900 和 390×844 下都不重叠、不裁切。

## 颜色语义（不要改）

| 语义 | 颜色 | 节点 kind |
| --- | --- | --- |
| 时间 / 时期 | 蓝 | `period` |
| 事件 | 琥珀 | `event` |
| 战役 | 橙红 | `battle` |
| 会议 / 文件 | 紫 | `meeting` / `document` |
| 人物 | 青 | `person` |
| 理论 / 概念 | 绿 | `theory` / `concept` |
| 易混 | 红 | `confuse`（或 `contrast` 边） |

## 扩展其他科目的建议

- 中特（10 个明确、五位一体）：`tree` 布局（后续加 dagre），节点用 `concept`。
- 马哲：`tree`，方向从左到右，边用 `part`。
- 经济：`chain` + 对比节点；供需曲线以后作为节点内的小 SVG，不参与布局。
- 法律：`matrix` 布局（情形 × 要件/效果），最需要新写布局器。
- 文学 / 古代史：`timeline`，阶段是朝代，泳道是体裁。
- 科技：`columns`（材料—特性—应用）。
